# Calendar helpers tools

The calendar cache scripts read (events, busy windows, towns; import after list_events), his local time while travelling, and the dated plans from his chats and mails that still need handling.

Generated by `tool gen` from packages/tools (domains/calendar.py): edit the registry, not this file. MCP server `hub` (tool `mcp__hub__<MCP name>`) and `tool call NAME '<json>' [--json]` run the same gateway and return the same result. Every input also takes `format`: concise (default) | detailed. Errors: {code, message, hint}; codes invalid_args, not_found, conflict, unavailable, timeout, rate_limited, approval_required, failed, internal. Each call logs one usage event (via=gateway, trace id, ms, code).

## calendar.events

Calendar events from the cache (titles, times, towns, travel flags), from today on. Fresh truth for
changes: the calendar tools (list_events).

Input:
- `days` (integer, default 7): from today on

Output: `count`, `events`, `note`
Example: `tool call calendar.events '{"days": 7}'`

## calendar.busy

Busy windows per day (timed events merged; free-marked ones count), evening busy 18–23, away the night
after, all-day markers.

Input:
- `date` (string /^(\d{4}-\d\d-\d\d|today|tomorrow|\+\d{1,2})$/, default "today"): YYYY-MM-DD, today, tomorrow or +N
- `days` (integer, default 1)

Output: `days`, `note`
Example: `tool call calendar.busy '{"date": "tomorrow"}'`
Example: `tool call calendar.busy '{"date": "2026-11-05", "days": 2}'`

## calendar.towns

The towns of each day's events (and train destinations), in order: where he will be.

Input:
- `date` (string /^(\d{4}-\d\d-\d\d|today|tomorrow|\+\d{1,2})$/, default "today"): YYYY-MM-DD, today, tomorrow or +N
- `days` (integer, default 1)

Output: `days`
Example: `tool call calendar.towns '{"date": "today"}'`

## calendar.cache

Age and size of the calendar cache (refresh when older than a day).

Input:
- (none)

Output: `cached`, `fetched`, `hours`, `events`, `window`
Example: `tool call calendar.cache '{}'`

## calendar.import

Refresh the cache from saved list_events results (the MCP JSON); consume deletes the inputs after.

Input:
- `files` (list of string, required): saved list_events results (JSON), absolute paths
- `days` (integer, default 21): window from today
- `consume` (boolean, default true): delete the input files after a successful import

Output: `events`, `travel`, `skipped`, `message` (concise leaves out message)
Example: `tool call calendar.import '{"files": ["/tmp/calendar-import.json"]}'`

## calendar.clock

His local time and zone (home outside trips; the trip's zone while away), and the same moment at home.

Input:
- `at` (string /^(\d{4}-\d\d-\d\d[ T]\d\d:\d\d(:\d\d)?([+-]\d\d:\d\d|Z)?|@\d{9,11})$/ (optional)): another moment (home wall time 'YYYY-MM-DD HH:MM', ISO with offset, @EPOCH); default now

Output: `local`, `zone`, `offset`, `home`, `home_zone`, `away`
Example: `tool call calendar.clock '{}'`
Example: `tool call calendar.clock '{"at": "2026-11-25 09:00"}'`

## calendar.plans

Dated plans from his chats and mails nobody handled yet (plans-watch, after the calendar and reminder
check): add, remind, ask or skip each, then calendar_plan_done.

Input:
- (none)

Output: `count`, `plans`
Example: `tool call calendar.plans '{}'`

## calendar.plan_done

Close plans-watch items: added (calendar) · reminded · asked (him) · skipped (not his / noise) · exists.

Input:
- `keys` (list of string /^[0-9a-f]{8}$/, required)
- `outcome` (added | reminded | asked | skipped | exists, required): added to the calendar · reminder set · asked him · not his / noise · already there
- `why` (string /^[A-Za-z0-9_-]{1,40}$/ (optional)): one word

Output: `acked`, `message`
Example: `tool call calendar.plan_done '{"keys": ["1a2b3c4d"], "outcome": "added"}'`

## CLI and cron

calcache (CLI, managed): the cache scripts read (train-watch, flight-watch, plans-watch, night plans), refreshed by the daily calcache-refresh note: list_events for 21 days → save the JSON → `calendar_import` (or `calcache import FILE --consume`). Titles and towns only: descriptions and streets are never cached. tripclock: his zone (home outside trips). plans-watch (cron */5): ~/inbox/vault-plans-*.md; every item ends with `calendar_plan_done` (= `plans-watch done KEY --as …`).
