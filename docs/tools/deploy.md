## deploy.status

What is deployed: the ~/bin release and drift, the land gate's mode and signed green lands, recent lands
with the hub runner's and local CI's seconds. For "what's deployed", "is the CI gate on", "did the last land
get a signed record".

Input:
- (none)

Output: `release`, `drift`, `gate`, `signed_green_lands`, `recent` (concise leaves out recent)
Example: `tool call deploy.status '{}'`

## deploy.run

Deploy main (or a main commit) to ~/bin (target bin) or as the hub release (target hub). plan=true (default)
changes nothing: hub = the plan (release, kit, CURRENT), bin = drift and the release that would go live. A hub
release with changed protected paths returns approval_required (his ✅, then again). Code reaches main only
through `assistant land`.

Input:
- `target` (bin | hub, default "bin"): bin = managed ~/bin files, hub = hub release
- `rev` (string /^[0-9a-f]{7,40}$/ (optional)): a main commit (default: main)
- `plan` (boolean, default true): only say what would happen; false = deploy

Output: `target`, `done`, `lines`
Example: `tool call deploy.run '{"target": "hub"}'`
Example: `tool call deploy.run '{"target": "bin", "plan": false}'`

## CLI and cron

`assistant` (CLI; tests in the repo): `assistant land BRANCH` (CI + the hub runner's signed record + the eval subset; `ci-gate status|shadow|enforce|off`), `assistant rollback [--target hub]`, `assistant cron`. Deploys here are the managed ~/bin files of main (target bin) and the hub release (target hub, loads through the loader; protected paths wait for his ✅).
