# Home Assistant tools

His Home Assistant through `ha`: privacy-gated states, history, logbook and automation traces; allowlisted writes (lights, switches, media, scenes, scripts, vacuum, helpers) with a read-back.

Generated by `tool gen` from packages/tools (domains/ha.py): edit the registry, not this file. MCP server `hub` (tool `mcp__hub__<MCP name>`) and `tool call NAME '<json>' [--json]` run the same gateway and return the same result. Every input also takes `format`: concise (default) | detailed. Errors: {code, message, hint}; codes invalid_args, not_found, conflict, unavailable, timeout, rate_limited, approval_required, failed, internal. Each call logs one usage event (via=gateway, trace id, ms, code).

## ha.state

One entity in detail (privacy-gated attributes); a name that fits several gives the short list.

Input:
- `entity` (string, required): an entity id (light.living_room) or a name ('ceiling lamp')

Output: `count`, `entities`
Example: `tool call ha.state '{"entity": "light.living_room"}'`
Example: `tool call ha.state '{"entity": "ceiling lamp"}'`

## ha.list

Entities with state, name and area, by domain and/or area (concise: no attributes).

Input:
- `domain` (string /^[a-z_]{2,30}$/ (optional)): light, switch, media_player, sensor, vacuum ...
- `area` (string (optional)): an area name (Living Room, Bedroom ...)
- `limit` (integer, default 100)

Output: `count`, `entities`
Example: `tool call ha.list '{"domain": "light"}'`
Example: `tool call ha.list '{"area": "Living Room"}'`

## ha.find

Fuzzy match on friendly name, entity id and area: the exact ids for the other tools.

Input:
- `words` (string, required): words of the name, id or area
- `domain` (string /^[a-z_]{2,30}$/ (optional))
- `limit` (integer, default 15)

Output: `count`, `entities`
Example: `tool call ha.find '{"words": "lamp"}'`

## ha.areas

Areas with entity counts per domain.

Input:
- (none)

Output: `areas`, `unassigned`
Example: `tool call ha.areas '{}'`

## ha.history

State changes of one entity with durations (recorder ~10 days). Location, network, notification and
Bluetooth entities stay hidden.

Input:
- `entity` (string, required): one entity id or name
- `since` (string /^(\d{1,4}[mhd]|\d\d:\d\d|\d{4}-\d\d-\d\d([T ]\d\d:\d\d(:\d\d)?([+-]\d\d:\d\d|Z)?)?)$/, default "24h"): 90m, 24h, 7d, HH:MM or ISO (the recorder keeps ~10 days)
- `until` (string /^(\d{1,4}[mhd]|\d\d:\d\d|\d{4}-\d\d-\d\d([T ]\d\d:\d\d(:\d\d)?([+-]\d\d:\d\d|Z)?)?)$/ (optional))
- `attrs` (list of string /^[a-z0-9_]{1,40}$/ (optional)): also these attributes (gated ones stay hidden)
- `limit` (integer, default 50)

Output: `entity_id`, `name`, `area`, `unit`, `since`, `until`, `changes`, `earlier_not_shown`, `attrs_not_seen`
Example: `tool call ha.history '{"entity": "vacuum.robot", "since": "7d"}'`

## ha.logbook

Logbook entries (who or what changed it); hidden entities are left out.

Input:
- `entity` (string (optional)): one entity (none: all, hidden ones left out)
- `since` (string /^(\d{1,4}[mhd]|\d\d:\d\d|\d{4}-\d\d-\d\d([T ]\d\d:\d\d(:\d\d)?([+-]\d\d:\d\d|Z)?)?)$/, default "24h")
- `until` (string /^(\d{1,4}[mhd]|\d\d:\d\d|\d{4}-\d\d-\d\d([T ]\d\d:\d\d(:\d\d)?([+-]\d\d:\d\d|Z)?)?)$/ (optional))
- `limit` (integer, default 40)

Output: `entity_id`, `since`, `until`, `entries`, `earlier_not_shown`, `hidden_entries`
Example: `tool call ha.logbook '{"entity": "automation.away_mode", "since": "7d"}'`

## ha.trace

Why an automation or script did (not) run: its last stored runs, summarised (trigger, conditions, steps,
errors; never variables or service data).

Input:
- `item` (string, required): an automation or script (id or name)
- `last` (integer, default 3)

Output: `entity_id`, `name`, `stored_runs`, `runs`
Example: `tool call ha.trace '{"item": "automation.arrival", "last": 3}'`

## ha.switch

Turn on, off or toggle: one name, entity ids, or an area (+ domain). Allowlisted domains only, read back.

Input:
- `dry_run` (boolean): resolve the targets and show them; send nothing
- `wait` (number, default 8.0): read-back timeout in seconds
- `action` (on | off | toggle, required)
- `targets` (list of string (optional)): one name, or entity ids (several only as ids)
- `area` (string (optional)): instead of targets: everything in an area
- `domain` (string /^[a-z_]{2,30}$/ (optional)): with area: only this domain (e.g. light)

Output: `confirmed`, `dry_run`, `changes`, `notes`
Example: `tool call ha.switch '{"action": "off", "targets": ["light.living_room"]}'`
Example: `tool call ha.switch '{"action": "off", "area": "Living Room", "domain": "light"}'`

## ha.set

Set a light (or an area's lights): brightness %, color temperature K, color name.

Input:
- `dry_run` (boolean): resolve the targets and show them; send nothing
- `wait` (number, default 8.0): read-back timeout in seconds
- `target` (string (optional)): one light (id or name)
- `area` (string (optional)): instead: all lights in an area
- `brightness` (integer (optional)): percent
- `color_temp` (integer (optional)): kelvin (2700 warm … 6500 cold)
- `color` (string /^[a-z]{3,20}$/ (optional)): a color name (red …)

Output: `confirmed`, `dry_run`, `changes`, `notes`
Example: `tool call ha.set '{"target": "light.living_room", "brightness": 30, "color_temp": 2700}'`

## ha.media

Control a media player: play, pause, stop, next, prev, mute, unmute, volume N.

Input:
- `dry_run` (boolean): resolve the targets and show them; send nothing
- `wait` (number, default 8.0): read-back timeout in seconds
- `player` (string, required): a media player (id or name)
- `action` (play | pause | stop | next | prev | mute | unmute | volume, required)
- `volume` (integer (optional)): with action volume: percent

Output: `confirmed`, `dry_run`, `changes`, `notes`
Example: `tool call ha.media '{"player": "media_player.tv", "action": "pause"}'`

## ha.run

Run a scene or a script (ones that touch locks, alarms or garages are refused by ha).

Input:
- `dry_run` (boolean): resolve the targets and show them; send nothing
- `wait` (number, default 8.0): read-back timeout in seconds
- `kind` (scene | script, required)
- `target` (string, required): the scene or script (id or name)

Output: `confirmed`, `dry_run`, `changes`, `notes`
Example: `tool call ha.run '{"kind": "scene", "target": "Movie"}'`

## ha.call

Any service on ha's allowlist for exactly one entity of that domain (vacuum, cover, climate, fan,
the writable helpers ...); ha checks the service, the data and the target, then reads back.

Input:
- `dry_run` (boolean): resolve the targets and show them; send nothing
- `wait` (number, default 8.0): read-back timeout in seconds
- `service` (string /^[a-z_]+\.[a-z_]+$/, required): domain.service on ha's allowlist
- `entity` (string, required): exactly one target entity (id or name) of that domain
- `data` (object (optional)): service data (no target keys)

Output: `confirmed`, `dry_run`, `changes`, `notes`
Example: `tool call ha.call '{"service": "vacuum.return_to_base", "entity": "vacuum.robot"}'`
Example: `tool call ha.call '{"service": "select.select_option", "entity": "select.robot_work_mode", "data": {"option": "vacuum"}}'`

## CLI and cron

`ha` (CLI, managed; skill home-assistant): the same reads and writes by hand, plus `--owner-ok "his words"` for garage/gate/door covers, switches, buttons and update.install (never a tool), `ha todo` (the shopping list: `shop`, skill shopping) and `ha device-url`. Exit: 0 ok, 1 HA/connection error, 2 refused/ambiguous, 3 sent but not confirmed (the tools return confirmed=false, never retry blindly). Cleanup, config and automations: ha-apply / ha-audit (admin, his ✅).
