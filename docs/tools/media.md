Generated by `tool gen` from packages/tools (domains/media.py): edit the registry, not this file. MCP server `hub` (tool `mcp__hub__<MCP name>`) and `tool call NAME '<json>' [--json]` run the same gateway and return the same result. Every input also takes `format`: concise (default) | detailed. Errors: {code, message, hint}; codes invalid_args, not_found, conflict, unavailable, timeout, rate_limited, approval_required, failed, internal. Each call logs one usage event (via=gateway, trace id, ms, code).

## media.search

Search Seerr (TMDB) for a title: year, type, TMDB id and whether it is on the server or requested.
Use first for "add/get X" (the TMDB id feeds media.request) and "is X on Emby".

Input:
- `query` (string, required): title words
- `type` (movie | tv (optional)): movie | tv (default both)
- `n` (integer, default 8)

Output: `count`, `results`, `like`
Example: `tool call media.search '{"query": "Dune"}'`
Example: `tool call media.search '{"query": "Severance", "type": "tv", "n": 3}'`

## media.status

Where a title stands: on Emby, requested (by whom), per-season state, live download progress.
For "is X downloaded yet", "how far is X". Requesters are his friends' display names: never relay them.

Input:
- `title` (string (optional)): title words
- `tmdb` (integer (optional)): TMDB id (needs type)
- `type` (movie | tv (optional))
- `n` (integer, default 1): how many search matches to show

Output: `count`, `titles`
Example: `tool call media.status '{"title": "Dune"}'`
Example: `tool call media.status '{"tmdb": 1399, "type": "tv"}'`

## media.doctor

Why a Seerr request has not reached Emby yet, with a German + English line he can forward.
Verdicts: not released, no release found, stuck import ... Diagnosis only (dry run): the routine fixes stay on
the CLI's weekly cron.

Input:
- `title` (string (optional)): one title (default: open requests)
- `type` (movie | tv (optional))
- `mine` (boolean): only his own requests (without title)
- `days` (integer, default 180): requests of the last N days (0 = all; without title)
- `probe` (boolean): also run interactive indexer searches (slower)
- `n` (integer, default 15)

Output: `items`, `dry_run`, `skipped`, `warnings`, `text`, `message` (concise leaves out message)
Example: `tool call media.doctor '{"title": "Dune: Part Three"}'`
Example: `tool call media.doctor '{"mine": true, "days": 60}'`

## media.request

Request a movie or show in Seerr (his user: auto-approved, then Radarr/Sonarr grab it).
Get the TMDB id from media.search first. Already requested / on the server / on the blocklist: not requested
again (result says why). tv: all open seasons unless seasons lists some.

Input:
- `tmdb` (integer, required): TMDB id (media.search shows it)
- `type` (movie | tv, required)
- `seasons` (list of integer (optional)): tv only: season numbers (default: all open seasons)
- `dry_run` (boolean): show what would be requested, send nothing

Output: `result`, `title`, `type`, `tmdb`, `request_id`, `request_status`, `seasons`, `skipped`, `reason`
Example: `tool call media.request '{"tmdb": 438631, "type": "movie"}'`
Example: `tool call media.request '{"tmdb": 1399, "type": "tv", "seasons": [1, 2], "dry_run": true}'`

## CLI and cron

`media` (CLI, managed; skills media-requests + media-help): the same reads by hand plus what is not a tool on purpose: play on the TV (`media play`, a Telegram button flow), tonight/group/franchise picks with buttons and polls, wrapped, posters, hogs/unwatched (never pitched: no media deletion), doctor's routine fixes (`media doctor` without --dry-run, weekly cron), ready-watch (cron, texts him when his requests land). Keys live in the CLI's secrets file and never reach a tool or its output.
