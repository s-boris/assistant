# Traces tools

My own traces, read-only: cost by trigger, his reply latency, failing tools, hook blocks, slowest turns and costliest agents (traces.db), gateway calls per tool, and Phoenix's span trees and slowest traces.

Generated by `tool gen` from packages/tools (domains/traces.py): edit the registry, not this file. MCP server `hub` (tool `mcp__hub__<MCP name>`) and `tool call NAME '<json>' [--json]` run the same gateway and return the same result. Every input also takes `format`: concise (default) | detailed. Errors: {code, message, hint}; codes invalid_args, not_found, conflict, unavailable, timeout, rate_limited, approval_required, failed, internal. Each call logs one usage event (via=gateway, trace id, ms, code).

## traces.report

My cost, his reply latency, failing tools, hook blocks, slowest turns and costliest agents, plus the gateway's
calls per tool. From traces.db (works without Phoenix). For "why was that slow", "what costs the most", "which
tools fail", the daily self-review and metric checks (G2 first reply, G3 failures).

Input:
- `days` (number, default 1.0): window in days back from now

Output: `days`, `cost`, `owner`, `errors`, `gateway`, `slowest`, `costliest_agents`, `slow_turns`, `agents`, `tool_counts`, `latency`, `gateway_tools` (concise leaves out slow_turns, agents, tool_counts, latency, gateway_tools)
Example: `tool call traces.report '{}'`
Example: `tool call traces.report '{"days": 3}'`

## traces.phoenix

Phoenix (the hub's trace store) as I feed it: health, forwarding counters, retention, traces in the window,
and how many of his turns have one joined trace. For "are traces landing", "is Phoenix ok".

Input:
- `hours` (integer, default 24): window in hours back from now

Output: `url`, `project`, `health`, `forwarding`, `retention`, `traces`, `joined`, `kept_out` (concise leaves out kept_out)
Example: `tool call traces.phoenix '{}'`

## traces.trace

One trace from Phoenix as a summary (detailed: its span rows): LLM calls, tools, gateway calls, agents,
errors, tokens and the slowest tools. For "why did that turn take so long", "what did that agent run do".

Input:
- `trace_id` (string /^(?:[0-9a-f]{32}|last)$/, required): a 32-hex trace id (traces.slow), or "last" = newest turn
- `limit` (integer, default 200): max spans returned (detailed)

Output: `summary`, `spans` (concise leaves out spans)
Example: `tool call traces.trace '{"trace_id": "last"}'`

## traces.slow

The slowest traces in Phoenix for the window, each with its span counts and slowest tools.
Use traces.trace on an id for the tree.

Input:
- `hours` (integer, default 24): window in hours back from now
- `top` (integer, default 5): how many traces

Output: `hours`, `traces`
Example: `tool call traces.slow '{}'`
Example: `tool call traces.slow '{"hours": 72, "top": 10}'`

## CLI and cron

`traces` (CLI, managed): `traces ingest` (cron */5) fills traces.db from the transcripts, `traces otel up` (cron */5) keeps the local OTLP receiver running; it stores Claude Code's own numbers in traces.db and forwards allowlisted spans to Phoenix (`traces phoenix status`; off: touch ~/.config/traces/phoenix-off). `traces brief` is the /traces answer, `traces agents` the subagent table, `traces phoenix joined` the share of his turns with one joined trace.
