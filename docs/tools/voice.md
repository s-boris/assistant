# Live voice tools

The voice relay (Gemini Live on his Telegram calls and the app): answer a hand-off in the call, ring him, the relay's state and call log (did he answer), a driving update, the Talk button. Only him.

Generated by `tool gen` from packages/tools (domains/voice.py): edit the registry, not this file. MCP server `hub` (tool `mcp__hub__<MCP name>`) and `tool call NAME '<json>' [--json]` run the same gateway and return the same result. Every input also takes `format`: concise (default) | detailed. Errors: {code, message, hint}; codes invalid_args, not_found, conflict, unavailable, timeout, rate_limited, approval_required, failed, internal. Each call logs one usage event (via=gateway, trace id, ms, code).

## voice.reply

Answer a live-voice hand-off (a 🗣️ event, via=voice) in the open call. not_delivered = the call ended: send it
on Telegram. more=true speaks a quick first part now and keeps the hand-off open for the rest.

Input:
- `id` (string /^[A-Za-z0-9_.:-]{1,32}$/, required): the hand-off id from the 🗣️ event
- `text` (string, required): 1-2 short spoken sentences
- `more` (boolean): a quick first part now; the rest follows with another reply

Output: `delivered`, `status`, `note`, `result`
Example: `tool call voice.reply '{"id": "v1", "text": "It's 14 degrees."}'`

## voice.call

Ring him (only him; 45 s, the relay's own limit of 3 an hour). answered = he picked up and the model opened
with the reason; not_answered / busy_or_limited = send it on Telegram.

Input:
- `reason` (string, required): why he is called (the opening line comes from it)
- `say` (string (optional)): exact spoken-friendly words to open with

Output: `delivered`, `status`, `note`, `result`
Example: `tool call voice.call '{"reason": "your train is cancelled"}'`

## voice.status

The relay's state: up, live sessions + calls, the call bridge. Counts and states only.

Input:
- (none)

Output: `up`, `live`, `tg_calls`, `result`

## voice.calls

The relay's call log (it stays in claude-hub-voice): the newest calls as metadata only, and for each call that
rang him whether he answered (from the ring itself, never guessed from words). outgoing=true lists only those.
detailed adds the quality numbers over `days` (`voice-relay stats`).

Input:
- `last` (integer, default 5): the newest calls to list (0 = numbers only)
- `outgoing` (boolean): only the calls that rang him (answered or not)
- `days` (number, default 7): the quality numbers over this many days (log: 14)

Output: `calls`, `outgoing`, `stats`, `live`

## voice.drive_update

Tell him something while he drives, his decided order: a call first; missed → a car message in the app; then a
short voice note (drive-update). The Telegram text is still yours to send.

Input:
- `text` (string, required): the update, short and spoken-friendly

Output: `delivered`, `status`, `note`, `result`
Example: `tool call voice.drive_update '{"text": "Stau vor dem Tunnel"}'`

## voice.talk

The 📞 Talk button: ring him once (lock: a second tap while it rings does nothing).

Input:
- (none)

Output: `delivered`, `status`, `note`, `result`

## voice.lookup

The voice relay's in-call quick lookups (way home, calendar, reminders, ...): one read-only CLI from the fast
lane's list, run here. For the relay in claude-hub-voice (principal voice); nothing else needs it.

Input:
- `argv` (list of string, required): a fast-lane command and its arguments
- `timeout_s` (number, default 3.0)

Output: `rc`, `out`

## CLI and cron

Spoken answers: 1-2 short sentences, no identifiers, numbers, links or private text (details on Telegram). A spoken request is never approval: side effects need his Telegram ✅. delivered=false with status not_delivered / ended = the call is over: send it on Telegram.
